# CAD 작업 하네싱

이 문서는 Zn-BDC automated synthesis용 로봇 합성 플랫폼과 실험실 자동화
모듈의 모든 CAD 작업에 공통 적용한다. 사용자가 이후 “하네싱”이라고 지정한
규칙은 기존 원칙과 충돌하지 않는 범위에서 이 문서에 추가한다.

## 1. 프로젝트 범위

- 목적은 개별 3D 프린팅 부품이 아니라 UR 로봇, 액체분주 모듈, 저울,
  소니케이터, 가열·교반기, 카메라 및 이송 치구가 함께 작동하는 실험실
  자동화 플랫폼을 설계하는 것이다.
- Ender-3는 프린터로 사용하는 것이 아니라 노즐 헤드를 제거하고 시린지
  펌프와 연동하는 액체분주 모션 모듈로 취급한다.
- 기본 단위는 항상 **mm**이다.

## 2. 치수 출처가 설계보다 우선한다

치수는 다음 네 종류로 구분해 기록한다.

| 표기 | 의미 | 사용 원칙 |
|---|---|---|
| `REFERENCE` | 제조사 도면·공식 STEP·공식 매뉴얼 | 가장 높은 우선순위 |
| `USER_CONFIRMED` | 사용자가 직접 제공·확정한 값 | 해당 설계에 확정 적용 |
| `MEASURED` | 이미지·PDF·실물에서 측정한 값 | 측정 방법과 오차 기록 |
| `ASSUMED` | 설계를 위해 새로 정한 값 | 확정값처럼 표현하지 않음 |

- 사용자가 정확한 도면을 제공하면 그 수치를 그대로 사용한다.
- 공식 STEP과 공식 치수도면이 다르면 차이를 보고하고 임의로 선택하지 않는다.
- 레퍼런스가 없으면 모델링보다 정확한 도면·데이터시트·제조사 CAD 확보를
  우선한다.
- 이미지 비율로 추정한 값은 `ASSUMED` 또는 `MEASURED`로 표시하고 제작용
  치수로 바로 사용하지 않는다.
- 제조사 원본 파일은 수정하지 않고 별도 작업 사본을 만든다.

## 3. CAD 기준 형식

- 파라메트릭 설계의 기준은 CadQuery 소스와 `parameters.py`이다.
- 제조사 형상은 제조사 STEP을 기준으로 유지한다.
- FreeCAD 및 조립 검토용 교환 파일은 STEP을 사용한다.
- AutoCAD/DXF/DWG는 2D 제조도면, 홀 위치, 외곽 가공 및 치수 표기층으로
  사용한다.
- STL·3MF는 출력과 배치 검토용 파생 파일이다. STL을 기준으로 정확한
  제작 치수를 역산하지 않는다.
- 저용량 STL은 원본 STEP/STL과 구분해 `_lowpoly` 또는 `_layout`을 붙인다.

## 4. 필수 작업 단계

1. 정확한 레퍼런스와 실제 모델명을 확인한다.
2. 필요한 치수를 모두 추출하고 `design_basis.md`에 출처를 정리한다.
3. 레퍼런스 치수와 새 설계 치수를 구분한다.
4. CadQuery 작업 소스와 파라미터 파일을 만든다.
5. 사용자 검토용 PNG와 STEP을 `Preview` 단계로 만든다.
6. 전체 치수, 체결, 간섭, 접근 방향과 추정 질량을 함께 제시한다.
7. 사용자 컨펌을 받는다.
8. 컨펌 후에만 최종 `Output` 또는 `Release`를 만든다.
9. 검증 결과와 변경 이력을 함께 저장한다.

컨펌 전 파일은 제조용 최종본으로 표현하지 않는다. 사용자가 기존 preview를
명시적으로 확정하면 그때 최종 release를 만들 수 있다.

## 5. 미리보기 요구사항

- PNG는 최소한 등각도와 체결부가 보이는 상면 또는 측면을 포함한다.
- 조립 STEP에는 부품별 색상을 사용하고, 참고 형상은 실제 제작 형상과 다른
  색으로 표시한다.
- 참고 바이알, 그리퍼 손가락, 로봇 또는 주변 장비가 STL에 포함되는지 여부를
  명시한다.
- 미리보기에는 외형 크기, 주요 홀·피치, 체결부 치수 및 기준 좌표를 표시한다.

## 6. 기계 검증

최종 CAD 생성 시 다음 항목을 확인한다.

- STEP 재가져오기 후 X/Y/Z bounding box
- STL의 boundary edge와 non-manifold edge가 0인지
- 홀 개수, 직경, 피치, edge margin, 탭/관통/블라인드 구분
- 최소 벽 두께, 홀 사이 web, 바닥 두께
- 볼트 머리·공구 접근 공간과 조립 순서
- 위치결정 핀, 장공 및 반복 탈착 기준
- 케이블, 튜브, 도어, 로봇 및 주변 장비와의 간섭
- 소니케이터 탱크·바스켓, 오븐 문·선반 등 실제 사용 공간 적합성

## 7. 로봇 취급 부품 검증

- 로봇 payload에는 그리퍼, 커플링, 어댑터, 트레이, 바이알, 캡 및 액체를
  모두 포함한다.
- 정적 무게만으로 승인하지 않고 무게중심, 관성, 가속·감속 및 비상정지를
  고려한다.
- 가능하면 마찰만으로 들지 않고 턱·홈·핀 등 form-fit 구조를 사용한다.
- 로봇 시험은 낮은 속도·가속도와 낮은 높이에서 시작하며 완제품의 실제
  질량과 무게중심을 입력한다.

## 8. 재료와 환경

- 온도, 용매, 산·염기, 초음파, 세척 방식에 따라 재료 적합성을 검토한다.
- Gray Resin 출력물은 형상·체결·동작 검증용 시제품으로 본다.
- PTFE, 알루미늄 및 스테인리스 최종품은 실제 질량과 가공 최소두께를 다시
  계산한다.
- 히터·오븐 주변에서는 수지의 열변형온도와 난연·화학적 위험을 확인한다.

## 9. 폴더와 이름 규칙

- 새 CAD는 `Modules/NN_Module_Name/` 아래에서 작업한다.
- 모듈 폴더에는 `00_STATUS.md`, References, Work, Preview, Output 역할이
  구분되어야 한다.
- 새 CAD 작업으로 파일이나 폴더를 추가할 때는 해당 상위 폴더에 이미 존재하는
  두 자리 숫자 prefix의 최댓값을 확인하고, 그 다음 숫자를 앞에 붙인다.
- `00_STATUS.md`는 상태 파일 전용으로 유지한다. 기존 항목의 번호를 다시
  매기거나 비어 있는 번호를 재사용하지 않으며, 같은 export 묶음의 파일도
  각각 고유한 다음 번호를 사용한다.
- 번호 prefix는 생성 순서와 추적성을 위한 것이며 `R01`, `R02` 같은 release
  revision을 대체하지 않는다. release revision도 별도로 증가시킨다.
- 파일명은 `장비_부품_핵심치수_상태_Rev` 순서를 권장한다.
- 공백과 특수문자보다 영문, 숫자, 밑줄을 사용한다.
- 예: `UR3e_Baseplate_1200x1000x12_Preview_R01.step`
- 기존 release를 덮어쓰지 않고 `R01`, `R02` 또는 `v1`, `v2`로 올린다.

### 모든 모듈의 버전별 저장과 필수 라우팅 (2026-10-27)

- 모든 설계 모듈의 작업 소스·미리보기·출력은 버전별 하위 폴더에 저장한다.
  `<다음번호>_Rxx/` 또는 `<다음번호>_<설계이름>_Rxx/`를 사용하며, 기존에
  버전이 명시된 폴더/legacy 링크는 그 구조를 유지한다. 모듈 루트나 버전이
  없는 Work/Preview/Output 위치에 새 CAD 파일을 평면으로 추가하지 않는다.
- 새 버전 작업을 시작할 때 공통 함수
  `Modules/90_Shared_Tools/05_Revision_Folders/01_revision_folders.py`의
  `revision_dir(parent, 'Rxx')`로 폴더를 먼저 확보한다. 같은 버전은 기존 폴더를
  사용하고, 새 버전은 다음 번호 폴더를 자동 생성한다. 번호는 최소 두 자리이며
  기존 100 이상 번호 뒤에서도 계속 증가한다.
- 새 생성 스크립트의 revision 선택과 파일명의 revision을 함께 갱신한다.
  다른 버전의 source/STEP를 읽을 때는 해당 버전 폴더를 명시한다.
- 매 작업 시작 시 `06_ROUTING.md`를 읽고 `04_revision_router.py prepare`로
  저장 위치를 확정한다. 매 작업 종료 전 `check --module <모듈>`을 통과시킨다.
  프로젝트 전체 정리 작업은 `check --all`을 사용한다. 모든 exporter의 출력
  디렉터리 선택은 `revision_dir()`를 거친다.
- 서로 다른 설계가 같은 R01을 쓰면 `family`로 분리한다. 기존 `V4`, `v1`,
  `REV_A/REV_B`도 그대로 지원한다. 버전 미확인 과거 파일은 `Unversioned`,
  공통 소스는 `Shared`에 두고 새 버전을 임의 추정하지 않는다.
- 제조사·사용자 원본 `01_References`, 이전 release와 삭제 이력은 보존한다.
  버전을 판별할 수 없는 파일은 임의로 최신 버전에 포함하지 않는다.
- 원본 참조·명명된 과거 variant·legacy 링크 예외는
  `05_Module_Routes.json`에 기록한다. 참조 내용을 수정하거나 과거 패키지를
  재생성하지 않고 작업 경로와 생성 스크립트의 경로만 갱신한다.

## 10. 작업 페이지 분리와 인수인계

- 하나의 Codex 작업 페이지에서는 한 모듈 또는 하나의 통합 검토만 다룬다.
- 새 작업 페이지를 시작할 때 전체 과거 대화를 복사하지 않는다.
- 대신 `AGENTS.md`, 이 문서, `PROJECT_INDEX.md`, 해당 모듈의
  `00_STATUS.md`와 필요한 레퍼런스만 읽는다.
- 작업 종료 시 `00_STATUS.md`에 확정 치수, 미확정 사항, 생성 파일,
  검증 결과와 다음 작업을 갱신한다.

## 11. 최종 release 구성

필요한 형식만 포함하되 일반적인 release는 다음으로 구성한다.

- CadQuery 소스와 `parameters.py`
- 편집 가능한 STEP
- 출력용 STL 또는 3MF
- 필요 시 DXF/DWG와 치수 PDF
- preview PNG
- `design_basis.md`
- `verification.txt`
- `README.md`
- 전달용 ZIP
